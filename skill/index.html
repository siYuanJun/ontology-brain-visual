business-to-ontology

把一段业务自然语言，按固定三步法拆解为「类 → 属性 → 关系」三层本体 JSON，并做回读自检。用户无需理解转换过程，Skill 自动完成。

输入

制度原文 · 业务场景 · 领域说明 · 条款段落

▼ 一段业务自然语言

处理

① 圈名词 → ② 三步判定 → ③ 统一命名 → ④ 输出 + 回读

▼ 固定四步工作流

输出

本体 JSON（classes / properties / relationships）+ 校验 + 自检回读

▲ 可供 RAG / 知识图谱 / Agent 使用

02 · WORKFLOW四步工作流

STEP 1 · 读取圈词

圈出业务名词

通读业务描述，圈出所有名词性概念（人物、对象、文件、事件、组织、场景）。先列候选清单，不急着分类。

⚠ 陷阱：漏圈隐含实体（如"重疾险"只算"重疾"）

STEP 2 · 三步判定

类 / 属性 / 关系

对每个候选依次问三问：是一类东西吗？是一个值吗？连接两个类吗？命中即归类。

⚠ 陷阱：把属性当类（"报案时间"不是独立类）

STEP 3 · 统一命名

命名规范

类名大驼峰、属性名下划线小写名词、关系名下划线小写动词。关系读法 = "A 动词 B"。

⚠ 陷阱：中英映射不一致（clause_id / 条款编号）

STEP 4 · 输出 + 回读

标准 JSON + 自检

按固定结构输出，不发明顶层字段。回读原文核对：每个类/属性/关系都有原文证据。

⚠ 陷阱：无证据建类（够用原则红线）

03 · DECISION MATRIX核心判定矩阵

问题命中条件归类落点
① 是一类东西吗？会被独立查询 · 有多个特征 · 有多个实例🔵 类 Classclasses 下的键
② 是一个值吗？只是描述某类的单一值，不会被独立查询🟡 属性 Property所属类的 properties 数组
③ 连接两个类吗？表示类与类之间如何关联🟢 关系 Relationshiprelationships 条目

命名规范

类名 = 大驼峰名词：InsuranceTypeDocument

属性名 = 下划线小写名词：clause_ideffective_date

关系名 = 下划线小写动词：applies_tobelongs_to

关系读法 = "A 动词 B"：Clause applies_to InsuranceType（条款适用于险种）
